# Effective Project Profile Deterministic Generator

This package is the `v0.0.6rc13` deterministic generation boundary for the
accepted Effective Project Profile semantics (`rc09`), canonical YAML
representation (`rc10`), parsed-instance schema (`rc11`), and source-aware
validation boundary (`rc12`).

Generate a profile for one exact project scope:

```text
python -m tools.scaf_effective_project_profile_generator.generator \
  --scope <project_scope_ref>
```

Or select another Project Application dataset:

```text
python -m tools.scaf_effective_project_profile_generator.generator \
  --scope <project_scope_ref> \
  --project-application <project-application.yaml>
```

Successful stdout contains **only canonical Effective Project Profile YAML** so
it can be redirected or piped without removing status text. The production CLI
does not write a persistent profile file itself.

The generator:

- captures the selected Project Application bytes before consumption;
- captures repository-owned authority/schema/normative inputs into a private validation boundary;
- requires the selected Project Application snapshot to pass the accepted rc07 validator;
- requires the frozen authority snapshot to pass the existing source-aware authority validator;
- derives the SCAF source release from validated Project Application records, or from the repository-owned accepted Project Application schema when the validated dataset contains zero records;
- derives the complete PAO domain dynamically for that source release;
- copies `applicable`, `not_applicable`, or `undetermined` only from a validated current exact-scope Project Application record;
- derives `no_current_disposition` only when that exact authority/scope pair is absent;
- binds the profile to SHA-256 of the exact captured Project Application bytes;
- serializes the accepted rc10 canonical mapping/entry order deterministically;
- self-validates the generated bytes with the accepted rc12 source-aware validator before returning or emitting them.

The production CLI exposes only the exact project scope and selected Project
Application file as project-side inputs. It does not expose repository root,
profile schema, Project Application schema, authority registry/schema, or
normative source substitution.

Generation does **not** decide whether an applicability judgment is correct,
resolve a project scope, approve rationale, exercise Project Design Authority,
recommend/select a Pattern, determine implementation or verification status,
prove compliance, accept risk, determine project completion, approve release,
or close engineering work.
