## 1. Decision Purpose

The independently reviewed rc05 source-aware validator established executable proof for one existing Consumption Selection. The remaining bounded gap is deterministic construction of that already accepted representation.

v0.0.7rc06 adds the first **Consumption Selection builder**.

Its purpose is deliberately narrow:

> **Construct one canonical rc03 Consumption Selection from one exact validated Effective Project Profile and explicit bounded selection inputs, then require the generated bytes to pass the accepted rc05 source-aware validator before return or CLI emission.**

The builder does not decide what is applicable, which Pattern should be used, which project artifacts belong in an AI context, whether evidence is sufficient, or whether work is complete.

## 5. Caller-Owned Inputs and Their Meaning

The builder accepts only bounded project/tool-owned construction inputs.

### 5.1 `selection_purpose`

One non-empty descriptive string. It records why a selection is being constructed. It is not an applicability, approval, compliance, release, or closure authority.

### 5.2 `state_selector`

A duplicate-free subset of the four frozen profile states:

```text
applicable
not_applicable
undetermined
no_current_disposition
```

Caller ordering is normalized to the accepted frozen canonical state order. An empty set is valid and deterministically produces no eligible entries.

### 5.3 `authority_mode` / `authority_ids`

Only the accepted two selector forms are supported:

```text
all_domain
explicit_set(exact scaf_authority_id values)
```

An explicit set may be empty. Exact IDs are canonicalized in lexical order. Unknown IDs are rejected against the validated source-profile domain.

No alias, title match, regex, semantic similarity, AI classifier, Pattern inference, or scope inference is accepted as authority identity.

### 5.4 `omitted_authority_ids` / `omission_basis`

The builder supports bounded omission without adding a ranking or token-budget algorithm.

If `omission_basis` is absent:

```text
bounded_omission.applied = false
omitted_authority_ids must be empty
I = E
```

If `omission_basis` is a non-empty descriptive string:

```text
bounded_omission.applied = true
O = exact caller-declared omitted_authority_ids
I = E - O
```

Every omitted ID must already be predicate-eligible. `applied:true` with an empty omitted set remains valid, preserving the accepted rc02/rc05 subset-or-equal semantics.

The omission basis does not decide priority, severity, applicability, compliance, or engineering importance.

## 6. Validation-First Source Consumption

The builder must not consume unvalidated profile state.

It captures:

```text
selected Effective Project Profile bytes
selected Project Application bytes
repository-owned Consumption Selection schema bytes
repository-owned Effective Project Profile schema bytes
repository-owned Project Application schema bytes
repository-owned authority registry/schema bytes
repository-owned canonical normative Markdown bytes
```

These sources are copied into a private temporary validation boundary.

Before deriving any selection entry, the exact captured profile is validated through the frozen v0.0.6 source-aware Effective Project Profile validator against the same captured Project Application snapshot and repository-owned source boundary.

Only after that proof passes may profile state be consumed for construction.

## 7. Representation Identity Is Repository-Owned

The builder does not invent a new serialization version.

It reads the repository-owned accepted Consumption Selection schema and derives:

```text
selection_kind: consumption_selection
representation_release: v0.0.7rc03
```

Therefore:

```text
rc06 builder version
!= Consumption Selection representation release
```

A representation change remains a separately reviewed contract change.

## 8. Deterministic Eligibility and Construction

From the validated profile:

```text
D = complete source-profile authority domain
```

The accepted eligibility rule remains exactly:

```text
E = {
      entry in D
      |
      entry.profile_state in state_selector
      AND
      entry.scaf_authority_id satisfies authority_selector
    }
```

The builder performs no arbitrary predicate evaluation.

Caller-declared exact omission gives:

```text
O = exact omitted_authority_ids
I = E - O
X = D - E
```

with the accepted relations:

```text
E = I + O
D = I + O + X
```

The builder does not serialize redundant authoritative E/O/X lists.

## 9. Selected-Entry Projection

Every included entry is projected directly from the validated source profile.

The projection preserves exactly:

```text
scaf_authority_id
profile_state
project_application_record_id when source state is recorded
```

For `no_current_disposition`, `project_application_record_id` remains absent.

Project Application rationale and project-side references remain upstream. The builder does not duplicate `disposition_basis`, decision references, authority references, supporting references, unresolved reasons, or awaiting references into Consumption Selection.

## 10. Complete / Filtered Derivation

The builder derives:

```text
complete
iff I = D and O = empty and X = empty

filtered
otherwise
```

The serialized `selection_class` is therefore a deterministic selection fact, not caller-owned engineering truth.

## 11. Canonical Serialization

Generated bytes preserve the accepted rc03 physical representation contract:

```text
exact nine-member root order
exact source_profile_binding order
quoted canonical string scalars
canonical frozen-state order
canonical authority-ID order
canonical bounded_omission shape/order
canonical selected-entry authority-ID order
canonical selected-entry member order
```

Empty arrays are serialized explicitly as `[]`; they are not represented as YAML nulls.

Ordering carries no priority, severity, risk, implementation sequence, review sequence, or AI-attention meaning.

## 12. Mandatory rc05 Self-Validation

Generated bytes are written only into the private temporary boundary and then passed through:

```text
validate_consumption_selection(...)
```

against:

```text
the same captured Effective Project Profile snapshot
the same captured Project Application snapshot
the same private repository-owned source boundary
```

If accepted rc05 validation fails, the builder raises a build error and returns/emits no successful Consumption Selection.

The self-validation requirement prevents the builder from becoming a second weaker interpretation of the representation/source contract.

## 14. Empty and Boundary Cases

The builder deliberately supports the already accepted valid edge cases:

```text
empty state_selector
empty explicit authority set
applied:true with O empty
all four states + all_domain -> complete selection
```

It rejects bounded invalid input before successful return, including:

```text
empty purpose
unknown or duplicate profile states
invalid authority mode
all_domain combined with explicit authority IDs
unknown / duplicate / empty explicit authority IDs
omitted IDs without omission basis
empty omission basis
unknown / duplicate omitted IDs
omitted IDs that are not predicate-eligible
invalid source profile
internally generated output rejected by rc05 self-validation
```

## 15. Authority Boundary

The central accepted distinctions remain unchanged:

```text
included in context != applicable
excluded from context != not_applicable
omitted != not_applicable
predicate excluded != bounded omitted
undetermined != no_current_disposition
```

Builder success means only:

```text
validated source profile
+

+

+
```

```text

```
